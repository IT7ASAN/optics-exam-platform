# منصة الامتحان المشترك – قسم تقنيات البصريات
### Optics Common Exam Platform · الثيم البنفسجي الملكي والتحكم الإداري الكامل

منصة ويب متكاملة، ثابتة (Static Web Application)، مصممة لطلبة قسم **تقنيات البصريات** للوصول إلى مقررات ومحاضرات الامتحان التقويمي الوزاري المشترك لجميع المراحل الدراسية، مع قارئ PDF مدمج، محرك بحث سريع، وتأثير التمرير السلس (Smooth Scrolling)، ولوحة تحكم متكاملة للمشرف (Admin Panel) لإدارة كافة نصوص الموقع وبطاقات الهيرو وصفحة حول المنصة، ورفع الملفات من الجهاز، وإدارة حسابات الطلاب مع تغيير الرموز واليوزرات.

## 🗄️ قاعدة البيانات: Supabase

كل بيانات المنصة محفوظة في **Supabase**، لذلك تعمل الحسابات والتعديلات على GitHub Pages مباشرة دون أي خادم Node.js:

| البيانات | مكان الحفظ في Supabase |
| :--- | :--- |
| نصوص وإعدادات المنصة (الهيرو، حول المنصة، المميزات...) | جدول `site_settings` |
| المراحل والمواد والمحاضرات | جداول `stages` و`subjects` و`lecture_files` |
| ملفات PDF المرفوعة | Storage bucket عام باسم `lectures` |
| حسابات الطلاب والمشرف | Supabase Auth + جدول `profiles` |

- إعدادات الاتصال (رابط المشروع والمفتاح العام anon) في `assets/js/supabase-config.js`. المفتاح العام آمن للنشر؛ الحماية عبر سياسات RLS: الجميع يقرأ المحتوى، والمشرف وحده يعدّل ويرفع الملفات.
- تصميم قاعدة البيانات والسياسات في `supabase/migrations/`، وإدارة الحسابات من لوحة المشرف (إنشاء/تعديل الرمز واليوزر/حذف) عبر Edge Function في `supabase/functions/admin-users/`.
- تسجيل الدخول يتم باسم المستخدم كما هو؛ داخلياً يُحوَّل إلى بريد `username@optics.local`، لذلك يجب أن يبقى خيار **Confirm email** معطلاً في إعدادات Auth.
- لترقية أي حساب إلى مشرف: من SQL Editor نفّذ `update profiles set role = 'admin' where username = 'اسم_المستخدم';`.
- لنقل محتوى `data/exams.json` وملفات PDF إلى قاعدة بيانات جديدة: `SUPABASE_URL=... SUPABASE_SERVICE_ROLE_KEY=... node scripts/migrate-to-supabase.mjs` (لا ترفع مفتاح service role إلى المستودع أبداً).
- ملف `data/exams.json` يبقى نسخة احتياطية تُستخدم فقط إذا تعذر الوصول إلى Supabase.

> **الطريقة القديمة (اختيارية):** GitHub Pages يستضيف ملفات ثابتة ولا يوفر API أو قاعدة بيانات. لتظهر حسابات الأجهزة الأخرى، انشر التطبيق الكامل على استضافة Node.js (مثل Render) واربط قرصاً دائماً واضبط `DATA_DIR` على مساره. بدون تخزين دائم قد تضيع الحسابات عند إعادة تشغيل الخادم. لا ترفع `data/users.json` إلى مستودع عام؛ الملف مستثنى من Git لأنه يحتوي بيانات الحسابات.

يوجد ملف `render.yaml` لإعداد نشر Node.js على Render مع قرص دائم. عيّن `ADMIN_PASSWORD` كمتغير سري قوي في إعدادات الخدمة؛ لا تستخدم كلمة المرور الافتراضية في الإنتاج. يجب أن تكون الواجهة وواجهات API على نفس النطاق كي تعمل الحسابات المشتركة.

المنصة تدعم التثبيت كتطبيق ويب تقدمي (PWA) من زر «تثبيت»؛ على iPhone استخدم Safari ثم «مشاركة» > «إضافة إلى الشاشة الرئيسية».

توجد نسخ `manifest.webmanifest` و`sw.js` في جذر المستودع لتعمل مباشرة على GitHub Pages، ونسخ مماثلة داخل `public/` ليضمّنها بناء Vite في مجلد `dist` عند تشغيل خادم Node.js.

## 🌟 مميزات المنصة والتحديثات الجديدة

1. **التحكم الشامل في جميع عناصر الموقع للمشرف**:
   - إمكانية تعديل اسم المنصة، اسم القسم، الكلية، والسنة الدراسية.
   - إمكانية تعديل نصوص وشارات الشاشة الرئيسية وقسم الهيرو (Hero Section).
   - **تعديل بطاقة قسم تقنيات البصريات التوضيحية**:
     - تعديل العنوان الأساسي للبطاقة.
     - تعديل النص الوصفي تحت العنوان.
     - تعديل وسوم التخصصات الأربعة («البصريات الهندسية»، «فحص الانكسار»، «العدسات اللاصقة»، «أمراض العين»).
   - **تعديل محتوى صفحة «حول المنصة»**: تعديل العنوان الرئيسي، العنوان الفرعي، والنبذة التعريفية الأكاديمية كاملة.

2. **رفع ملفات PDF من ملفات الجهاز مباشرة**:
   - تخصيص حقل لرفع الملف من جهاز الكمبيوتر أو الهاتف عند إضافة أو تعديل محاضرة.
   - قراءة الملف وحفظه محلياً في المتصفح مع استخراج الاسم والحجم وعدد الصفحات تلقائياً.
   - فتح الملف وتصفحه فوراً داخل **قارئ PDF الداخلي** دون الحاجة لرفعه إلى سيرفر خارجي!

3. **نظام حسابات المستخدمين والطلاب المسجلين**:
   - إمكانية إنشاء حساب جديد لأي طالب عبر إدخال (الاسم الكامل، اسم المستخدم/يوزر نيم، رمز المرور، والمرحلة الدراسية).
   - إخفاء بيانات المشرف من واجهة تسجيل الدخول لحماية الخصوصية.
   - **قسم إدارة المستخدمين في لوحة المشرف**:
     - عرض جدول بجميع حسابات الطلاب المسجلين مع تاريخ التسجيل والمرحلة.
     - إمكانية تغيير رمز المرور واسم المستخدم لأي طالب مباشرة من لوحة المشرف.
     - إمكانية إضافة حسابات جديدة أو حذف أي حساب طالب.

4. **الثيم البنفسجي الملكي والتمرير السلس**:
   - تصميم Apple بنفسجي راقٍ يدعم الوضعين الداكن والفاتح.
   - تمرير سلس (Smooth Scrolling) انسيابي بين أقسام الصفحة الرئيسية.

### الإجابة القاطعة:
**نعم، يجب رفع ملفات المشروع كاملة إلى مستودع GitHub لأول مرة فقط.**

- **لماذا؟**
  لأن خدمة **GitHub Pages** هي استضافة لموقعك؛ لكي يفتح الموقع على رابط مثل `https://username.github.io/optics-exam-platform/`، يحتاج GitHub إلى الملفات الأساسية (`index.html`، مجلد `assets`، مجلد `data`، مجلد `files`).
  - إذا كان المستودع فارغاً، فإن إدخال بيانات المستودع والـ Token في لوحة الإدارة **لن ينشئ الموقع**، لأن الـ Token وظيفته: **تحديث ملف البيانات `exams.json` بعد أن يكون الموقع مرفوعاً بالفعل!**

### إذن ما هو الترتيب الصحيح للعمل؟

| المرحلة | ما الذي تفعله؟ | كم مرة؟ |
| :--- | :--- | :--- |
| **المرحلة 1: التأسيس الأول** | رفع ملفات المشروع كاملة إلى مستودع GitHub وتفعيل GitHub Pages من Settings > Pages. (يمكنك ضغط زر **«📦 تحميل حزمة المشروع ZIP»** من لوحة الإدارة لرفعها بضغطة واحدة). | **مرة واحدة فقط في البداية** |
| **المرحلة 2: التحديثات اليومية** | تعديل المواد والمحاضرات من لوحة الإدارة ثم استخدام **الطريقة الأولى (بنقرة زر عبر Token)** أو **الطريقة الثانية (استبدال exams.json)**. | **في كل مرة تعدل فيها محتوى** (دون الحاجة لإعادة رفع المشروع كاملاً أبداً!) |

## 🚀 كيفية استخدام الطريقة الأولى والثانية في رفع التحديثات

### الطريقة الأولى: النشر التلقائي بنقرة زر واحدة عبر GitHub API (موصى بها)
1. ادخل إلى لوحة تحكم المشرف بحساب `it7asan`.
2. اذهب للتبويب رقم **5: نشر ومزامنة البيانات للجميع**.
3. أدخل اسم مستودعك (مثال: `yourname/optics-exam-platform`).
4. أدخل رمز وصول GitHub (Personal Access Token) مع صلاحية `repo`.
5. اضغط زر **«🔍 فحص واختبار الاتصال والتوكن»** للتأكد من صحة الإعدادات.
6. اضغط زر **«🚀 نشر التعديلات فوراً لجميع الطلاب على GitHub»** (أو الزر السريع الأخضر بأعلى لوحة الإدارة).
7. سيتصل الموقع بـ GitHub مباشرة ويقوم بعمل Commit وتحديث لملف `data/exams.json`. خلال 30 إلى 60 ثانية، يعيد GitHub Pages النشر وتظهر التعديلات لجميع الطلاب حول العالم!

### الطريقة الثانية: النشر اليدوي باستبدال ملف exams.json (بدون الحاجة لأي Token)
1. بعد تعديل المواد أو المحاضرات أو الإعدادات في لوحة المشرف، اضغط زر **«📥 1. تحميل ملف exams.json المحدّث»**.
2. اضغط زر **«📂 2. فتح مجلد data في مستودعك على GitHub»** (أو افتح مستودعك على GitHub وادخل لمجلد `data`).
3. اضغط `Add file` > `Upload files` واسحب ملف `exams.json` الذي قمت بتنزيله، ثم اضغط الزر الأخضر **Commit changes**.
4. فوراً سيعيد GitHub Pages البناء ويظهر التحديث لجميع الطلبة.

## 🚀 النشر على GitHub Pages

1. ارفع المشروع إلى مستودع GitHub الخاص بك:
   ```bash
   git init
   git add .
   git commit -m "Optics Platform Full Admin Customization & User Management"
   git branch -M main
   git remote add origin https://github.com/USERNAME/optics-exam-platform.git
   git push -u origin main
   ```
2. في GitHub، ادخل إلى **Settings** > **Pages**.
3. اختر الفرع `main` والمجلد `/ (root)` ثم اضغط **Save**.
4. سيعمل الموقع مباشرة على: `https://USERNAME.github.io/optics-exam-platform/`.
